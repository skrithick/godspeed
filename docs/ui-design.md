# UI design notes

## What changed and why

The earlier overview looked more like a landing page than a place to resume work: a large tinted hero, three matching cards, several icon tiles, and a second AI promotion all competed with the recent-page list. There was a similar pattern in the task table (color on almost every field), and the shell repeated local-storage status in three places. [Design commentary on repetitive generated interfaces](https://superdesign.dev/blog/why-ai-design-looks-generic) helped identify patterns to audit; these patterns are not evidence that any particular UI was AI-generated.

- **Hierarchy before decoration.** [Nielsen Norman Group’s visual hierarchy](https://www.nngroup.com/articles/visual-hierarchy-ux-definition/) and [aesthetic and minimalist design](https://www.nngroup.com/articles/aesthetic-minimalist-design/) guidance informed the smaller, unboxed masthead and lists. Keep the Godspeed wordmark, flight artwork, and serif accent; use spacing and type to distinguish groups before adding a border. Reserve outlines for editable controls and surfaces where containment matters, such as dialogs and draggable task cards. Use a single divider role for scanning rows.
- **Make routes recognizable.** [Recognition rather than recall](https://www.nngroup.com/articles/recognition-and-recall/) informed keeping labeled navigation, showing recently edited pages and named views in search, and giving the full page browser a specific entry point. Workspace destinations are links, so browser actions like open in a new tab still work. The small-screen drawer traps focus and supports Escape; search is also directly available in the header.
- **Color means something.** [Carbon’s color roles](https://carbondesignsystem.com/building-blocks/foundations/color/overview) informed neutral surfaces in both themes and separate roles for dividers, field boundaries, selected states, focus, and the lime brand/action accent. Lime fills use dark ink and a distinct control edge; readable foreground accents are separate from the fill. Emerald and amber accompany explicit status labels instead of replacing them. Shadows mainly distinguish temporary surfaces like menus and dialogs.
- **Type supports scanning.** Geist carries interface text, Geist Mono marks structured details such as calendar labels, dates, shortcuts and tool names, and Fraunces is reserved for the wordmark and editorial headings.
- **Keep the conversation readable.** Chat answers come first; sources and proposed changes stay visible alongside the response, while diagnostic tool inputs and outputs are one disclosure away.
- **Keep controls consistent.** [shadcn/ui Radix Select](https://ui.shadcn.com/docs/components/radix/select) and [Dropdown Menu](https://ui.shadcn.com/docs/components/radix/dropdown-menu) are adapted to Godspeed’s field and menu tokens. Field fills distinguish inputs at rest; a separate focus color marks keyboard navigation.
- **Keep selection consistent.** A short accent marker indicates the active sidebar item, command result, or context-menu action. First-run guidance uses empty states rather than example records.
- **Calendar hierarchy.** [Carbon’s date-picker guidance](https://carbondesignsystem.com/building-blocks/core/components/date-picker/guidelines) informed the visual distinction between today, dates in the current month, and adjacent months. [FullCalendar’s DayGrid](https://fullcalendar.io/docs/daygrid-view) informed the month layout and grouped navigation. Narrow screens use task counts in the grid and readable task names in an agenda below it.
- **One task workspace.** Table, Board, and Calendar share the same filters and records. The table keeps the task column in view while scrolling and uses labeled status and due-date treatments to make active work easier to scan. One main creation button serves all views; a calendar date can still prefill a due date.
- **Workspace chrome.** A fading radial dot pattern sits behind every view. Route and settings transitions are brief and respect reduced motion. The desktop sidebar saves its expanded width and icon-rail state locally; the mobile drawer remains independent. Menus and dialogs lightly blur the surface behind them without changing the focus or dismissal behavior.
- **Keep feedback and controls perceivable.** Reference [WCAG 2.2 text contrast](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html), [non-text contrast](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html), and [target size](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html). Browser tests check the contrast of key theme tokens, keyboard selection and focus return, and narrow layouts. These are targeted checks, not a full accessibility conformance audit.
